## CRITICAL（已实测复现）

### C1 · 标记擦除器会把标记后面的正文整段吃掉

**位置**：`client.js` L1847 `MEM_STRIP_RE` + L1861 `MEM_PARTIAL_RE` + L1944-L1949

**实测**（用真实正则跑）：

```
输入: "<!--mem-log topic=x\n正文里有 `code`\n-->\n\n这是用户看到的正文"
输出: ""                                    ← 正文被整段吃掉

输入: "<!--mem-log topic=x 正文 --> 这是用户看到的正文"
输出: ""                                    ← 同样吃掉
```

**根因**：`MEM_STRIP_RE` 的 `[^`]*?` 排除反引号 → 含反引号的标记匹配不上；随后
`MEM_PARTIAL_RE` 的 `[\s\S]*$` 贪婪到末尾 → 把标记之后的全部正文删掉。

**后果**：会话显示内容永久消失（历史节点不再重渲染）。这是「事故 2：内容永久消失」的原样复发。

### C2 · 「显示已停用」勾选框无效，删除文案承诺的「可恢复」是假的

**位置**：`client.js` L733 + L367；`index.js` L4293

**证据链**：
- `client.js:733` — 勾选时**不传** status：`if (!showInactive) params.set('status', 'active')`
- `index.js:4293` — 后端回落到 active：`status: q.get('status') || 'active'`
- `client.js:367` — 文案承诺：`` `#${item.id} 已删除（软删除，可恢复）` ``

**后果**：`status='deleted'` 的条目在 GUI 里**永远列不出来**，界面内没有任何恢复路径。
误点一次删除，条目从界面彻底消失。文案与接口行为相反。

### C3 · 收尾语模板把占位符当字面量，模型「照抄」写出垃圾数据

**位置**：`index.js` L2735-L2736、L2839-L2840（usageLines）

**已发生的事实**（不是假设）：真实库 `logs id=213`：

```
summary  = "≤35字"
keywords = "词A｜词B"
text     = "正文写在这里"
```

**根因**：注入里写「整行照抄即可」，而模板里 `text='正文'`、`summary='≤35字'` 等
**不是格式说明，是会被原样提交的值**。

**后果**：写入成功、无报错，但该条不进「记忆索引」，对下一个会话完全隐形。

### C4 · writeHeartbeat 读失败会用模板整体覆盖用户 policy.md

**位置**：`index.js` L3360-L3365 + L3414

```js
try {
  current = readFileSync(store.paths.policy, 'utf8')
} catch {
  current = POLICY_TEMPLATE      // ← 读失败被当成「文件不存在」
}
...
await atomicWrite(store.paths.policy, updated)   // ← 无条件写回
```

**后果**：文件被占用 / 瞬时 IO 错误（Windows 常见）→ 用模板整体覆盖，
用户手改的规则、收尾语、排版一次性全丢，**返回 200 成功**。

**对比**：`readIfExists`（L501-508）只吞 ENOENT、其余 rethrow —— 这里正好相反。

但有 7 条 HIGH，其中**三条确定性 bug**（子代理已用 node 实跑复现）：

### H-new1 · `isInside` 把 `..foo` 这类正常子目录误判为越界（1 行正则）
```js
rel.startsWith('..')   // '..backup' → true → 判成「在 root 外」
```
后果：迁移守卫失效、项目目录不跟随、`wroteMemory` 漏记。改法：`!/^\.\.($|[\\/])/.test(rel)`。

### H-new2 · `PACKAGE_VERSION` 用 URL.pathname 不去码
路径含空格/中文（`%20`、`%E5%BC%A0`）→ readFileSync ENOENT → 被 catch 吞成空串 →
GUI 版本号永久不显示。改法：`fileURLToPath(import.meta.url)`。

### H-new3 · `copyTree` 用文本读写复制任意文件
```js
const text = await readIfExists(source)   // utf8 解码
await atomicWrite(target, text)            // 重新编码写回
```
实测 14 字节 PNG → 写回 24 字节，内容全变。**迁移根目录时，用户放进记忆目录的任何图片/压缩包都会被静默破坏。**

### H-new4 · 指针失效后静默新建空库（最伤用户感知）
`readPointer` 把所有异常吞成 undefined → 盘离线/盘符变了 → 走「首次安装」分支 →
**新建空 memory.db 并覆盖指针**。用户看到「记忆全没了」，原库还在旧位置但指针已丢。
**建议：指针存在但目标不可用时必须硬停报错，不能当首次安装。**

### H-new5 · capScore 被转折加成顶穿
`capScore` 承诺「弱词无论如何修饰都封顶在强阈值下」，但转折 ×1.4 在它**之后**执行。
实测「不行，但是很有意思」→ 夸赞 0.854（strong），承诺失效。

### H-new6 · `looksIronic` 把真诚道谢判成吐槽
词表含 `谢谢啊/真贴心/辛苦了呢`，且「报错+谢谢」共现即判反讽 →
**先删掉正确的喜悦/友善/爱意**，只留一条 0.8 吐槽。实测「报错修好了，谢谢」被判成吐槽。

### H-new7 · `atomicWrite` 的 EPERM fallback 先删原文件
```js
await unlink(path)   // ← 原文件在这里就没了
await rename(temp, path)  // 第二次再失败 = 文件永久丢失
```
影响 state.json（项目映射 + policySyncVersion）与 policy.md。
