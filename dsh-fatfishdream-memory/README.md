# 大肥鱼的梦 · dsh-fatfishdream-memory

给 [DeepSeek Harness](https://github.com/deepseek-ai)（DSH）用的**长期记忆插件**。

它让 AI 跨会话记得「我们之前一起做过什么」——不是记得更多技术细节，
而是记得**这段关系里发生过什么**。

写入方式很特别：**不注册任何工具**。模型在回复正文里写几行标记，插件监听
会话事件、自己入库；结论每轮以纯文本注入。所以它不会把会话搞崩，也不需要
文件读写权限。

> **状态**：`1.0.0`，MIT 许可。当前从 GitHub 安装；npm 发布后可直接
> `add dsh-fatfishdream-memory`。

---

## 它解决什么问题

DSH 的会话是隔离的。关掉窗口再打开，AI 不知道昨天你们改过什么、踩过什么坑、
你说过不喜欢什么。

这个插件补上那一层：每轮对话自动注入「当前项目的结论」，模型照常干活时
顺手把值得留的写下来，下一轮/下次会话就能读到。

**它不做什么**：不替你思考、不做语义检索、不联网、不调用任何外部服务。
就是一个本地的 SQLite 库 + 一套注入与写入通道。

---

## 适合谁用

**个人开发者，或一两个人维护的小项目。**

典型场景：一个长期做下去的项目，会话会断、窗口会关，
但「上次那个坑踩过没有」「我说过不喜欢什么」不该跟着断。

本插件最初就是为这个场景写的 —— 它假定记忆属于**一个人**，
所以不做多用户、不做跨设备同步、不做集中审计。
需要这些能力的团队与平台场景，它不是合适的选择。

---

## 四条通道（零工具）

| 能力 | 走哪条通道 | 模型要做什么 |
|---|---|---|
| **读** | `systemPrompt.context` 每轮注入结论 | 什么都不用做，内容已经在上下文里 |
| **写** | 回复正文里写 `mem-log` 标记 | 顺手写几行，插件监听 `session/event` 自己入库 |
| **查** | 本机 HTTP 接口 | 用 pwsh 发请求 |
| **情绪** | 插件自动监听用户消息 | 完全无感知 |

**为什么不做成工具**：工具 schema 会进每次请求的 `tools` 数组，某些反代/中转
通道（实测 WorkBuddy）会以「参数结构不符合要求」**拒绝整个请求** ——
该 profile 下所有会话都发不出消息。本项目因此实际中断过两次，
每次都要用户手动卸载插件才能恢复。

所以这里做了个反向选择：**放弃工具的便利，换取「永远不会因为自己而让会话发不出消息」**。

## 装它

```bash
# 从 GitHub 直接装（插件在仓库的子目录里，用 #path: 指定）
dsh plugin --profile <你的profile> add "git+https://github.com/FatFishNet/dsh-fatfishdream-memory.git#path:/dsh-fatfishdream-memory"

# 已经 clone 到本地的话，直接指向包目录
dsh plugin --profile <你的profile> add <clone 路径>/dsh-fatfishdream-memory
```

装完**完整重启 DSH**（不是禁用→启用，是重启客户端 —— 客户端代码是浏览器模块，
禁用启用不会重新加载它）。

> **尚未发布到 npm。** 发布后才会多一条 `add dsh-fatfishdream-memory`，
> 那时上面两种装法仍然可用。
**确认装对了**：看 DSH 日志里的

```
[health-check-verdict] 通过：9 项全部就位
```

9 项分别是 4 个事件监听、注入层、`/memory` 命令、HTTP 路由、库可读、根目录可读。
缺一项它会明确说哪一项坏了 —— 这是为「DSH 升级后插件静默失效」准备的。

装好后侧边栏出现「大肥鱼的梦」图标，点开是六个页签：

| 页签 | 干什么 |
|---|---|
| 用户画像 | 跨项目的事实与偏好，可增删改停用 |
| 规则与偏好 | 按项目维护的约定，可按项目/类型筛选 |
| 情绪记录 | 插件自动录的，可纠正误判 |
| 记忆流水 | 模型写的工作日志，按项目+时间筛选 |
| 收尾语 | 每轮固定结尾那句话 |
| 存储设置 | 记忆根目录迁移、库体积构成 |

## 怎么用（模型侧）

### 写记忆：在回复正文里写标记

```
<!--mem-log topic=开发日志 summary=修好并发写库丢失 keywords=FTS｜bm25
正文写在这里，可以多行
-->
```

**参数顺序固定 `topic` → `summary` → `keywords`，且与 topic 同一行。**
写反时后面的参数会被前一个整段吞掉（summary 丢失、keywords 被污染），
**而且不报错**。

| 参数 | 要求 |
|---|---|
| `topic` | 13 个分类之一，封闭集合，不在其中的会被白名单拒收 |
| `summary` | 一句话说清这条讲了什么，**≤35 字**；超了会被截断（会记诊断日志） |
| `keywords` | 检索用的技术名词，用全角竖线 `｜` 分隔（**不要用逗号**）；抽不出就写 `无` |

**13 个 topic**：开发日志 / 技术讨论 / 构建/编译 / 注入/预算 / 插件/装载 /
路径/沙箱 / 格式/编码 / 文档/行号 / 情绪判据 / 用户画像 / 数据清理 / GUI/界面 / Git

**三条禁令**（每条都实际踩过，`node --check` 查不出来）：

| 禁止 | 会发生什么 |
|---|---|
| 写 `<!--/mem-log-->` 这类闭合标签 | 不会被剥离，变成正文**永久写进库并每轮注入** |
| 开标签自带 `-->` 后再加闭合标签 | 同上 |
| 整条压成一行 `<!--mem-log topic=x 正文 -->` | **正则匹配不上，整条静默丢失，无任何报错** |
| topic 与正文同行 | 正文会被整段吃进 topic，结果是一条空正文（**会跳过，但有诊断日志**） |

**收尾的 `-->` 必须单独起一行。** 正文里要提到标记字样就拆开写
（反引号包住也不行 —— 解析器看原文，不看渲染结果）。

### 查记忆：本机 HTTP 接口

```powershell
# 结论层检索（scope 必带，不传返回 400）
$env:DSH_WEB_URL/api/dsh-memory/search?q=<关键词>&scope=<项目名>&summary=1

# 先看摘要省 token，确认相关再按 id 取全文
$env:DSH_WEB_URL/api/dsh-memory/entry?id=<id>&table=<table>

# 原文层回溯（不在默认 search 里）
$env:DSH_WEB_URL/api/dsh-memory/archive?scope=<项目名>&q=<关键词>&limit=50
```

| 端点 | 结果字段 | 说明 |
|---|---|---|
| `/search` | `hits` | 只搜结论层（流水 / 规则 / 画像） |
| `/archive` | `rows` | 只搜原文层，分页 `limit` / `offset` |
| `/entries` | `entries` | GUI 翻页用，**`table` 必填**（四张表 id 各自编号） |
| `/entry` | `entry` | 按 id 取单条，必须带 `table` |

**端口每次启动都变**，必须读 `$env:DSH_WEB_URL`，不要写死。

**检索只查 `profile` / `rules` / `logs` 三张表**：`archive` 是原文层（会把结论淹掉），
`emotion` 是个人记录（不进上下文也不需要查询）。

**结果顺序是三张表轮流取**：`profile → rules → logs → profile → …`，各表内部按相关度。
这样做是因为三张表的 bm25 分数是各自语料算的、跨表比大小没有意义。
**所以同一张表连续出现是正常的**，不是排序坏了。

## 情绪捕获

用户表达情绪时插件自己识别入库，**模型无感知**。

- **六簇**：爱意 / 夸赞 / 吐槽 / 友善 / 喜悦 / 低落
- 判定 = 情感词典打分 + 否定/程度/转折三条语言学规则 + 反讽检测
- **命中即记**：每条都入库，只标「强 / 弱」两档，**不按阈值丢弃**
- 只认真人消息：代码块、行内代码、引号内被讨论的字样、URL 都不计入
- **不进检索、不进注入**：它只给用户自己在 GUI 里看，是「个人兴趣记录」而不是可检索知识

> 为什么「命中即记」而不筛选：判错了还能回 `archive` 原文追溯，判漏了就永远没了。
> 误判靠扩充复合词词典修，**不要退回按阈值丢**。

## 存在哪

单库 SQLite（`<记忆根目录>/memory.db`，WAL 模式），四张业务表 + 一张原文层：

| 表 | 存什么 | 注入吗 | 谁写 |
|---|---|---|---|
| `profile` | 用户画像（跨项目） | ✅ 每轮 | 用户在 GUI |
| `rules` | 规则与偏好（带 `scope` / `kind`） | ✅ 按项目 | 用户在 GUI |
| `emotion` | 情绪记录 | ❌ 也不进检索 | 插件自动 |
| `logs` | 记忆流水 | ❌ 只检索 | 模型标记 |
| `archive` | user/assistant **原文一条不落** | ❌ 只按 `/archive` 回溯 | 插件自动 |

> ⚠️ `archive` **只从 2026-11-14 04:45（v4 上线）开始有原文**，更早的对话没有回填。
> 所以它查不到时要说「我没有这段记录」，不能说「没发生过」。

**`logs` 是结论层**（整理过的），**`archive` 是原文层**（不可变、可追溯）。
整理会漏会判错，但只要原文还在就还能翻回来 —— 这是「记忆就是完整的，而不是取舍」的落地方式。

根目录选址、表结构、FTS 设计、备份与迁移、体积构成，见 **[STORAGE.md](STORAGE.md)**。

## 已知限制（真实存在，不粉饰）

| 限制 | 说明 |
|---|---|
| **macOS 未验证** | 选址逻辑假设 Windows 盘符体系，会静默落到怪路径。**跨平台请先看 STORAGE.md 的选址一节** |
| **`archive` 只增不减** | 没有保留期或体积上限，膨胀比约 6×（5000 轮 ≈ 118 MB） |
| **情绪理解不了反讽** | 词典 + 规则，客套、压抑、委婉否定识别不了 |
| **标记写错会静默丢** | 整条压成一行会完全不匹配、零报错、整条丢失（见「三条禁令」） |
| **注入随内容增长** | 上限约 4 KB / 900 token 每轮（内容少就少花，不是固定扣这么多） |
| **项目段预算 4096 字节** | 写满要人进 GUI 精简或标 stale，没有自动压缩 |
| **不支持多实例并发** | 插件假定只有一个 DSH 实例；同时开两个会互相踩（后写覆盖先写），但不会损坏库 |
| **检索是关键词，不是语义** | 换个说法就搜不到（中文按字切分，2 字词能搜到，同义词不行） |
