### ☐ TC-05 防循环闸门必须存在（**这条最关键，失败会导致客户端卡死**）

**背景**：DSH 的 `agent/turn-stopping` 契约写着，在它里面 `steer` 会让
**本轮不关闭、多跑一步**。阈值改成 1 后每个漏记轮都会 steer，
**若没有闸门就是无限循环**：

```
没写 → steer → 多跑一步 → 还是没写 → 再 steer → …
```

后果：token 烧光 + 客户端可能卡死。**这条必须优先验。**

**怎么跑**

```powershell
Select-String -Path dsh-fatfishdream-memory\index.js -Pattern "fatfishSteerGuard|FATFISH_STEER_GUARD_KEY|alreadyNudgedThisTurn"
```

**预期**：至少命中这三类

| 符号 | 作用 |
|---|---|
| `const fatfishSteerGuard = new Map()` | 存「哪个 turn 已提醒过」 |
| `` FATFISH_STEER_GUARD_KEY = `${PLUGIN_SOURCE_KIND}:steer` `` | 键前缀（带包名，防与其他插件撞） |
| `if (failStreak >= ... && !alreadyNudgedThisTurn)` | **闸门真正生效的地方** |

**判失败条件**：
- 缺 `fatfishSteerGuard`
- 或 if 条件里**没有** `!alreadyNudgedThisTurn`（那样每轮都会 steer → 无限循环）

### ☐ TC-06 提醒文案必须包含「不要重复收尾语」（**这条决定双收尾语会不会回来**）

**怎么跑**

```powershell
Select-String -Path dsh-fatfishdream-memory\index.js -Pattern "补完就结束，不要再重复一遍收尾语"
```

**预期**：命中 1 处

**为什么**：同一轮会出现两条消息 ——「正常回答」和「补写流水」。
如果不说明「补写不是新回复」，模型会给两条都加收尾语。
实测 83 个 turn 里 29 个这样（35%）。

**判失败条件**：没命中 → 双收尾语会立刻回来

---

### ☐ TC-07 运行时的**真实行为**：漏 1 轮就提醒

**这条是唯一能验证「阈值 1 真的生效」的黑盒测试。**

**怎么跑**

1. **让本会话有一轮不写流水**（最省事的办法：直接问一个不需要动手的问题，
   然后**不要** POST `/log`）
2. 等这一轮结束（DSH 会触发 `turn-stopping`）
3. 看日志：

```powershell
$log = "D:\dsh-fatfishdream-memory\logs\$(Get-Date -Format yyyy-MM-dd).log"
Select-String -Path $log -Pattern "write-fail-reminder" | Select-Object -Last 3
```

**预期**

```json
{"streak":1,"delivered":true,"turn":N}
```

**三个必须同时成立：**

| 字段 | 期望 | 说明 |
|---|---|---|
| `streak` | **1** | 若为 2 → 还是旧阈值 |
| `delivered` | `true` | 投递成功 |
| `turn` | **数字** | 旧版没有这个字段 |

**判失败条件**：任一不符

### ☐ TC-08 同一轮**不得**重复提醒

**怎么跑**

连续几轮之后，检查日志里同一个 `turn` 是否出现两次：

```powershell
$log = "D:\dsh-fatfishdream-memory\logs\$(Get-Date -Format yyyy-MM-dd).log"
Select-String -Path $log -Pattern '"turn":(\d+)' |
  Where-Object { $_.Line -match 'write-fail-reminder' } |
  ForEach-Object { [regex]::Match($_.Line, '"turn":(\d+)').Groups[1].Value } |
  Group-Object | Where-Object Count -gt 1
```

**预期**：**无输出**（没有重复的 turn）

**判失败条件**：有输出 → 闸门失效，**可能导致无限循环，请立即停用插件**

### ☐ TC-09 同一轮**只能有 1 条收尾语**（双收尾语的正面验证）

**怎么跑**

```powershell
$r = Invoke-RestMethod "$env:DSH_WEB_URL/api/dsh-memory/archive?limit=200"
$r.rows |
  Where-Object { $_.role -eq 'assistant' -and $_.turn -ne $null } |
  Group-Object turn |
  ForEach-Object {
    $n = @($_.Group | Where-Object { $_.text -match '等待下一轮任务' }).Count
    if ($n -gt 1) { "❌ turn=$($_.Name) 有 $n 条收尾语" }
  }
```

**预期**：最近几轮（改动生效之后的）**无输出**

**⚠️ 注意**：改动**之前**的老 turn 仍然会有 2 条，那是历史数据，不算失败。
只检查**装上新版之后**的 turn。

**判失败条件**：新 turn 出现 2 条 → TC-06 的文案没生效

## 6. 已知的、**不算 bug** 的现象

避免你误判：

| 现象 | 是不是 bug | 说明 |
|---|---|---|
| 注入里 `## 全局结论` / `## 全局规则` 字节数与你不同 | **不是** | 那是用户数据（profile/rules 表） |
| 每轮都会被提醒写流水 | **不是** | 阈值 1 的设计意图，**每一轮都在兜底** |
| 老 turn 里有 2 条收尾语 | **不是** | 历史数据，改动前产生的 |
| `write-streak-check` 每轮都出现 | **不是** | 它本来就是每轮结算的诊断 |
| 提醒对用户不可见 | **不是** | `steer` 的消息不进界面，只给模型看 |
