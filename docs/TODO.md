## 情绪记录只存模板句（text 混了元数据）

**状态**：已知设计债，暂缓
**记录时间**：2026-11-14（v5 已让它退出检索，这条讲的是数据本身的形状）
**优先级**：低（退出检索后已不影响检索质量）

### 现在是什么

`emotion.text` 存的是**模板句**，不是原话：

```
用户表达爱意（喜欢·高置信·0.90）：大肥鱼我喜欢你
         ↑分类  ↑证据  ↑置信度      ↑原话
```

而 `cls` / `evidence` / `confidence` / `score` **本来就有独立列** ——
同样的信息存了两遍，还把展示层的排版混进了数据层。

### 为什么当初这样写

`text` 是四张表共用的列（GUI 列表、`getById`、`/entries` 都读它），
早先 GUI 只有一个「正文」字段，模板句让列表一眼能看出「谁说了什么情绪」。
独立列是后来才补的。

### v5 之后的实际影响

- **检索**：已不受影响（emotion 退出 `/search`，模板词不再污染）；
- **GUI 情绪页签**：`text` 显示成整句模板，其实**比只有原话更好读**
  （能直接看到 cls 和证据）。所以这个「债」在 UI 上反而是特性。

### 真要改的话

改成 `text = quote`，然后 GUI 情绪页签自己拼
`用户表达{cls}（{evidence}·{confidence}）：{text}`。

**前提**：先改 GUI 渲染，再迁数据 —— 顺序反了会让界面短暂显示成「只有原话」，
丢失 cls/evidence 的可见性（那正是用户天天看的东西）。

## archive 原文层没有保留期 / 体积上限

**状态**：暂缓（先观察真实增长速度）
**记录时间**：2026-11-14
**优先级**：中（`archive` 只增不减，长期会撑大 `memory.db`）

### 现在是什么

v4 起 user / assistant 的**原文一条不落**都进 `archive`，
包括 reasoning-distill 之类的注入型消息（单条可能上万字）。
目前**没有任何清理策略**：不按时间过期、不按体积截断。

### 为什么先不做限制

用户当时的原话是「记忆就是完整的，而不是取舍」。一上来就加保留期，
等于又用「判断」丢信息 —— 而且现在还没有增长数据，限制只能靠猜。

### 什么时候该做

看 `GET /api/dsh-memory/state` 里的 `db.size`，以及 `db.archive` 条数：

- 库体积明显膨胀（比如 > 100 MB）→ 先加**按时间**的保留期（如 180 天），
  而不是按条数，时间语义更好解释；
- 只想留近期原文 → 加「归档最近 N 天」的配置项，默认关闭。

### 做的时候必须注意

1. **不要动 `logs` / `emotion`** —— 那是结论层，体积本来就小，
   按 `kind` 一刀切删过用户的东西是硬约束 8 的教训。
2. 删除必须**同时**清 `archive_fts`（contentless 表不能 `DELETE`，
   见 `docs/维护手册.md` §3），否则会出现「表里没有但搜得到」。
3. 任何自动删除都先做**预览 + 用户确认**，不做静默清理。

## ⚠️ macOS 兼容（跨平台风险）

**状态**：未处理，暂缓
**记录时间**：2026-11-12
**优先级**：低（当前只自用 Windows），但**别人装可能踩坑**

### 问题

插件所有选址逻辑都假设 Windows 盘符体系。macOS 用户装上后不会崩溃，
但会**静默走到错误的位置**，事后找不到数据。

### 具体表现

| 位置 | 代码 | macOS 后果 |
|---|---|---|
| `cordis.patch.yml` | `root: 'D:\dsh-fatfishdream-memory'` | **最严重**：第 1 级「config 指定」直接命中并返回，后面四级选址全被跳过；`resolve()` 会把它变成工作区里一个叫 `D:\dsh-fatfishdream-memory` 的怪目录 |
| `systemDriveLetter()` | 读 `SystemDrive`，默认 `'C'` | 变量不存在，恒返回 `'C'`；`isSystemDriveTarget()` 对 POSIX 路径恒为 false |
| `listCandidateDrives()` | 循环 `D:`~`Z:`，`statSync("D:\\")` | 全部不存在，返回空数组 |
| `systemFallbackRoot()` | `join(home, 'Documents')` | ✅ **这一条恰好能用**（macOS 也是 `~/Documents`） |
| `client.js` 面板 | "可用磁盘（非系统盘）：D: 剩…" | 列表永远为空 |
| 迁移功能 | 迁移到盘符路径 | 失败 |

**记忆读写本身能用** —— 只要根目录是合法 POSIX 路径，`join` / `readFile` / `writeFile` 都正常。
坏的只是**选址**和**迁移**。

### 最小修复（3 处）

```js
// 1. 加平台常量
const IS_WIN = process.platform === 'win32'

// 2. 非 Windows 没有盘符探测
function listCandidateDrives() {
  if (!IS_WIN) return []
  ...
}

// 3. cordis.patch.yml 的 root 改成 'auto'，让它走自动选址
//    默认落点：~/Documents/dsh-fatfishdream-memory（与 Windows 兜底一致）
```

### 还要决定的

- 默认位置：`~/Documents/dsh-fatfishdream-memory`（跟 Windows 一致）
  还是 `~/Library/Application Support/dsh-fatfishdream-memory`（更符合 macOS 惯例）
- `PREFERRED_DRIVE = 'D'` 只在 Windows 有意义，非 Windows 分支应跳过它

### 但建议先做一个防护

**最小成本、防最坏情况**：检测到「非 Windows 且配置里是盘符路径」时，
打警告并改用自动选址。这样至少不会让记忆静默写进一个叫 `D:\...` 的怪目录。

## 相似流水去重工具（用户手动选择性删除）

**状态**：暂缓（**流水已清空，当前 0 条，没有可去重的数据**）
**记录时间**：2026-11-14
**优先级**：低（等有新流水、且用户觉得需要时再做）

### 需求

做一个**工具**，找出记忆库里高度相似的流水，**把选择权交给用户** ——
工具只负责「识别 + 展示 + 提供删除入口」，删哪条由用户在 GUI 里决定。

**明确不做的事**：不自动去重、不自动删除。理由：相似的条目可能是
「同一件事记了两遍」（该删旧的），也可能是「同一件事的两个阶段」（都该留），
程序分不清，只有用户知道。

### 清空前的实测（留作参考，当前数据已清空）

```
开头 30 字相同的流水：3 组，每组 2 条
  ids 340/341  「读了 dsh-skill-switch 源码 src/...」
  ids 142/146  「更新 docs/USAGE-FOR-OTHER-PROJ...」
  ids 135/136  「USAGE-FOR-OTHER-PROJECTS.md ...」
rules 表：无重复（用户手工维护，干净）
```

448 条流水里约 6 条疑似重复，占 1.3%。

### 实现思路（待细化）

1. **相似判定**：先用最简单的「正文前 N 字相同」或「文本编辑距离 / 公共前缀长度」
   做候选集，不要上语义相似度（成本高且不可解释）
2. **展示**：GUI 里新增一处「疑似重复」列表，成组展示，每组显示时间、topic、摘要
3. **操作**：每组内提供「保留这条吗」的选择，删除走已有的
   `/api/dsh-memory/entry/delete`（软删除，可恢复）
4. **绝不自动执行**：所有删除都是用户点出来的

### 相关背景

2026-11-14 讨论「命中两条接近的记忆怎么办」时定的口径：
- 检索时**不去重**，返回标号 + 摘要 + 时间戳，让模型自己判断
- 重复清理是**数据维护**，属于用户的事，不是模型能擅自做的
