# 大肥鱼的梦

给 [DeepSeek Harness](https://github.com/deepseek-ai)（下称 DSH）用的长期记忆插件。

让模型在新会话里仍记得：**你是什么样的人**、**这个项目有哪些约定**、**上次做到哪儿了**。

只依赖 DSH 客户端内置的 Node.js 原生 SQLite 模块，**零第三方运行时依赖**。

> 版本 `1.4.0` · MIT 许可 · [npm](https://www.npmjs.com/package/dsh-fatfishdream-memory)

---

## 安装

```bash
dsh plugin --profile <profile> add dsh-fatfishdream-memory
```

装完**必须完整重启 DSH 客户端**。

> 禁用再启用**不能替代重启**。`client.js` 是浏览器模块，禁用/启用不会让浏览器
> 重新加载它 —— 你会以为新版本没生效。

装成功的判据是日志里出现：

```
[health-check-verdict] 通过：10 项全部就位
```

然后侧边栏会出现「大肥鱼的梦」入口。

## 它是怎么工作的

**不注册任何工具。**

这一点是刻意的，不是省事。工具 schema 会进入每次请求的 `tools` 数组，而**反向代理
适配器本身是一个可替换的插件** —— 当前用的这个（已实测 WorkBuddy）不认 `tools`
数组，会以「参数结构不符合要求」为由**拒绝整个请求** —— 结果是该 profile 下所有会话
都发不出消息，必须手动卸载插件才能恢复。

> ⚠️ **这不是 DSH 禁止注册工具。** DSH 允许注册（`tools` 是每轮请求的正式字段），
> 换一个认 `tools` 的 adapter 就能绕过。本插件不注册，是为了**在当前适配器下也不会
> 拖垮会话**，是「选哪个适配器」的取舍，不是「被协议禁止」。

所以各通道长这样：

| 能力 | 通道 | 模型要做什么 |
|---|---|---|
| 读 | `systemPrompt.context` 每轮注入结论 | 什么都不用做 |
| 写 | 工作区脚本 `log.ps1` → 本机 `POST /api/dsh-memory/log` | 一行命令 |
| 查 | 本机 HTTP 接口 | 用 pwsh 发一次请求 |
| 情绪 | 监听用户消息自动记录 | 无感知 |

一句话：**用工具调用的能力，换「不因自己导致会话不可用」。**

## 漏记会自动补上（2026-11-20 新增）

**这套系统唯一的失效方式是「模型忘了写流水」，而它没有任何症状** ——
日志干净、界面正常、`health` 全绿，只是那段记忆不存在。

所以 1.4.0 加了一条兜底链路：

```
turn/end  →  判定本轮没写  →  用 prepareCall 直接问模型「这一轮该记什么」
          →  拿到一句话  →  POST /api/dsh-memory/log（带 backfill:true）
```

| 项 | 说明 |
|---|---|
| 触发时机 | 每轮结束（`turn/end`），异步执行，**不阻塞对话** |
| 用什么模型 | 你当前选的那个（继承 `agentDefaultModel`，不额外配置） |
| 耗时 | 实测约 **2 秒**（不占用主对话的等待时间） |
| 落库位置 | 和普通流水一样，进 `logs` 表 |
| 内容来源 | **模型产出**，插件只负责把文本 POST 进库 |

**怎么知道它工作过**：查诊断日志里的 `backfill-done`，带 `id` 与 `durationMs`。

```
2026-11-21T13:58:06.136 [backfill-done] {"id":1268,"durationMs":2441,"text":"…"}
```

**它不会无限重试**：4xx（请求本身错了）不重试；5xx / 429 / 网络异常会释放重试机会。
如果一直看到 `backfill-failed` 而没有 `backfill-done`，把那几行发给作者。

> ⚠️ **补记失败不影响主会话** —— 整条链路包在 try 里，任何异常只写诊断日志。

## 写流水：一行命令（2026-11-18 起）

**插件会自动在每个工作区放一个短命令脚本**，调用形状只有一个：

```powershell
& .\.dsh-fatfishdream-memory\log.ps1 "一句话结论"
```

括号里那句是**唯一要想的事**（正文 ≤150 字，最多 5 行）。
`cwd` / `sessionId` / JSON 编码 / `Content-Type` / POST 方法全部固化在脚本里；
`topic` 不传补「开发日志」、`summary` 不传从正文截取，都由服务端处理。

需要精确控制时可加第二个参数：

```powershell
& .\.dsh-fatfishdream-memory\log.ps1 "改了注入文案" "注入/预算"
```

### 这个目录是什么

```
<工作区>/.dsh-fatfishdream-memory/
  log.ps1       写流水短命令（1599 字节）
  README.txt    给使用者看的说明
```

它与 `.dsh/`（技能开关状态）、`.dsh-handoff/`（交接文档）同类 —— **只对本机有意义的运行时状态**。
如果工作区提交进 git，建议自己把它加进 `.gitignore`（插件**不会**替你改那个文件）：

```gitignore
.dsh-fatfishdream-memory/
```

### 什么时候生成 / 什么时候更新

该工作区**发生第一次对话**时（`agent/created`）自动创建。

**更新判据是「内容」，不是「存在」**（2026-11-19 修）：

| 情形 | 行为 |
|---|---|
| 文件不存在 | 建目录、写两个文件 |
| 内容与模板**一致** | 什么都不做（不白写盘） |
| 内容与模板**不一致** | **覆写为最新模板** ← 插件升级后靠这条同步 |
| 删掉整个目录 | 下次对话会重建 |

> **⚠️ 为什么「已存在 → 什么都不做」是错的**：插件升级改了模板，已经生成过的
> 工作区会**永远停在旧版本**，而且一个字都不报。实测踩过：三个工作区的
> `log.ps1` 全停在一天前（718 字节 vs 模板 1599 字节），新加的 `turnWrites`
> 输出**一次都没执行过**。现在改为比 sha256，不一致就覆写。
>
> **代价**：如果你自己改过 `log.ps1`（比如加调试输出），会被静默覆盖。
> 想加调试请改插件源码里的 `WORKSPACE_LOG_PS1` —— 那才是唯一真相源。

**新工作区的第一轮**可能还没生成，此时退回下面的长命令。

> **为什么要有脚本**：同一套注入里，「每轮收尾语」（一句固定文字）从未漏过一次，
> 而「写流水」实测漏 58%。差别在**决策数量** —— 收尾语 0 个决策，写流水 6 个
> （想内容 / 压字数 / 选 topic / 写 summary / 拼 JSON / 记住两个必填参数）。
> 脚本把它压到 1 个。

### 没有脚本时的长命令（兜底）

```powershell
Invoke-RestMethod -Method Post "$env:DSH_WEB_URL/api/dsh-memory/log" `
  -ContentType 'application/json' `
  -Body (@{
    text      = '正文'
    sessionId = $env:DSH_SESSION_ID
    cwd       = (Get-Location).Path
  } | ConvertTo-Json)
```

`topic` 不传时补「开发日志」，`summary` 不传时从正文截取。

> **为什么改短**：`cwd` 和 `sessionId` 省掉会写错项目 / 被误判成没写，这两个必带；
> 其余参数省掉只是用了默认值。参数越多越容易「嫌麻烦就不写了」。

要精确控制时再补全：

```powershell
Invoke-RestMethod -Method Post "$env:DSH_WEB_URL/api/dsh-memory/log" `
  -ContentType 'application/json' `
  -Body (@{
    text      = '正文'
    topic     = '开发日志'
    summary   = '≤35 字概述'
    keywords  = '词A｜词B'
    sessionId = $env:DSH_SESSION_ID
    cwd       = (Get-Location).Path
  } | ConvertTo-Json)
```

| 参数 | 约束 |
|---|---|
| `text` | **必填**，为空返回 400 |
| `topic` | **可省**（补「开发日志」）；传了就必须是 14 个分类之一 —— **可省 ≠ 可以乱写**，写错仍返回 400 |
| `summary` | **可省**（从正文截取，去 markdown 记号 + 35 字截断）；传了超长会截断 |
| `keywords` | 全角竖线 `｜` 分隔；无名词写 `无` |
| `scope` | 可省，省略时按 `cwd` 解析 |
| `cwd` | **目录必须存在**，否则 400 |
| `sessionId` | 建议传，否则「连续未写」提醒会误报 |

> `summary` 选**截取**而不是留空，是因为它是**检索与注入都依赖**的字段 ——
> 留空等于「写了但搜不到」，比不写更坏。

14 个 topic：开发日志 / 技术讨论 / 构建/编译 / 注入/预算 / 插件/装载 / 路径/沙箱 /
格式/编码 / 文档/行号 / 情绪判据 / 用户画像 / 数据清理 / GUI/界面 / Git / 闲聊

### 为什么不用「正文标记」

早期版本是让模型在回复里内嵌一段标记，插件解析后落库。功能上没问题，但标记
**必须出现在正文里**，于是界面只剩两种结局：

- **不擦** → 永久占屏，窗口一小就看不见正文；
- **擦** → 先在流式输出里显示、再被抹掉，也就是**闪烁**。

这两者是同一件事的两种状态。前六代擦除器都在「擦得更隐蔽」上打补丁，分别栽在
跨段误伤、内容永久消失、React 重建反复闪、全局 CSS 打断滚动条、等静止再擦、
切会话仍闪上 —— 因为病根不在擦法，在**标记本不该进正文**。

改成 HTTP 之后顺带省了 token：一条长标记约 300~600 token，还会永久留在会话
上下文里，按 10 轮算就是几千 token 的纯开销。

### 兜底：正文标记仍然可用

HTTP 不通时（端口变化、接口异常）可以退回写标记，插件照样入库：

```
<!--mem-log topic=开发日志 summary=概述 keywords=词A｜词B
正文
-->
```

参数顺序固定 `topic` → `summary` → `keywords` 且与 `topic` 同行，写反会静默丢摘要。

三条禁止（`node --check` 查不出）：

| 禁止 | 后果 |
|---|---|
| 写 `<!--/mem-log-->` 这类闭合标签 | 不会被剥离，永久入库并逐轮注入 |
| 开标签自带 `-->` 后再加闭合标签 | 同上 |
| 整条压成一行 | 正则不匹配，**整条静默丢失**，零报错 |

## 查记忆

```powershell
# 结论层（scope 必填，缺省 400）
$env:DSH_WEB_URL/api/dsh-memory/search?q=<关键词>&scope=<项目名>&summary=1

# 按 id 取全文（table 必填，四表 id 各自编号）
$env:DSH_WEB_URL/api/dsh-memory/entry?id=<id>&table=<table>

# 原文层回溯
$env:DSH_WEB_URL/api/dsh-memory/archive?scope=<项目名>&q=<关键词>&limit=50
```

| 端点 | 字段 | 说明 |
|---|---|---|
| `/search` | `hits` | 只查结论层（流水 / 规则 / 画像） |
| `/archive` | `rows` | 只查原文层，分页 `limit` / `offset` |
| `/entries` | `entries` | 分页列表，`table` 必填 |
| `/entry` | `entry` | 单条，须带 `table` |

**端口每次启动都变**，读 `$env:DSH_WEB_URL`，别硬编码。

检索是**三表轮流取样**（`profile → rules → logs`），表内按相关度排。
同一张表连续出现是正常的。

| 页签 | 用途 |
|---|---|
| 用户画像 | 跨项目的事实与偏好 |
| 规则与偏好 | 按项目维护的约定 |
| 情绪记录 | 自动记录，可人工修正 |
| 记忆流水 | 模型写的工作日志 |
| 工作区改名 | 改名或合并，带迁前迁后数据量比对 |
| 收尾语 | 每轮固定结尾语句 |
| 存储设置 | 根目录迁移、库体积构成 |

## 存储

单库 SQLite（`<记忆根目录>/memory.db`，WAL 模式）：

| 表 | 内容 | 注入 | 谁写 |
|---|---|---|---|
| `profile` | 用户画像（跨项目） | 每轮 | 你在 GUI |
| `rules` | 规则与偏好 | 按项目 | 你在 GUI |
| `emotion` | 情绪记录 | 否，也不进检索 | 插件自动 |
| `logs` | 记忆流水 | 否，仅检索 | 模型经 HTTP |
| `archive` | 原文逐条留存 | 否，仅 `/archive` | 插件自动 |

**结论层 vs 原文层**：`logs` 是整理过的结论，会漏也会错；`archive` 是一条不落的
原文，不可变。检索默认只查结论层 —— 否则原文会淹没结论。要追溯才走 `/archive`。

> `archive` 从 2026-11-14 04:45（v4）起才有。查不到时说「无此段记录」，
> 而不是「没发生过」。

`emotion` 是唯一**既不注入也不进检索**的表，只给你自己看。搜不到它是设计如此。

细节（根目录选址、FTS 设计、备份迁移、体积构成）见 [STORAGE.md](STORAGE.md)。

## 情绪捕获

插件自动识别用户消息里的情绪并记录，模型无感知。

- 六类：爱意 / 夸赞 / 吐槽 / 友善 / 喜悦 / 低落
- 词典打分 + 否定 / 程度 / 转折规则 + 反讽检测 + 后置限定词降权
- **命中即记**，`confidence` 只标强（≥0.62）/ 弱，不按阈值丢弃
- 只处理真实用户消息（代码块、行内代码、被引用的内容、URL 不计入）
- 不注入、不进检索，只在 GUI 里给你看

> 为什么命中即记：误判可以靠 `archive` 追溯，**漏判则永久丢失**。
> 修正误判靠扩充词典，不退回按阈值丢弃。

## 已知限制

| 限制 | 说明 |
|---|---|
| macOS 未验证 | 选址逻辑基于 Windows 盘符体系 |
| `archive` 只增不减 | 无保留期、无上限，膨胀比约 6× |
| 旧会话仍会闪 | 换通道前的历史消息含标记，切过去会闪一下。不会再增加 |
| 情绪识别不了反讽 | 词典 + 规则，识别不了客套、压抑、委婉否定 |
| 检索是关键词匹配 | 非语义，换个说法就命中不到 |
| 不支持多实例 | 同时开两个 DSH 会互相覆盖（不致损坏库） |
| **派生文件的自愈时机** | `log.ps1` 只在**会话创建时**（`agent/created`）检查并修复，**不是每轮**。会话中途删掉它，要等下一个新会话才恢复 |
| **手改 `log.ps1` 会被覆盖** | 内容比对是 sha256，不一致就覆写。要定制请改插件源码里的模板常量 |
| **检索词里的控制字符会被剔除** | `\u0000`~`\u001F` 与 `\u007F` 一律换成空格。查询词只含这些字符时返回 0 条 |
| **补记用的是你当前的模型** | 它不额外配置模型。你换模型，补记跟着换；模型不可用时补记会失败（有日志，不影响对话） |
| **补记只能补「模型自己判断该记什么」** | 它看到的是一轮的 user/assistant 原文，**看不到工具调用的细节**。所以它写的是结论，不是操作流水 |
| **正文里单独一行的 HTML 注释会被擦掉** | 1.4.0 起生效（以前只擦 `mem-*`）。要在回复里展示注释原文，请放进代码块 |
